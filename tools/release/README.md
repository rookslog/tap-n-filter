# Tagged release automation

`release.yml` admits only `vX.Y.Z` and `vX.Y.Z-beta.N` tags at exact commits reachable from protected `main`. It checks both local ancestry and current GitHub tag/main identity. Tag text enters Python through environment variables, never shell source. Existing macOS 15 and 26 runners build the exact commit with latest-stable Xcode, `swift build` and default `swift test` in release configuration with two jobs. Native engine, device, audio and window tests remain opt-in and disabled. Neither the app nor its probe/engine tools are launched.

Only the executable, its complete nested SwiftPM resource bundle and source Info.plist enter the ad-hoc-signed app. No test bundles, helper executables, data or local audit files are copied. The normal library branch needs no external helper; owned probe tooling is not part of this package. Signature, architecture and resource correspondence checks run before archiving and after a ditto archive extraction. No Developer ID lookup, signing-account access or notarization occurs. Ad-hoc signing is not notarization and does not remove Gatekeeper requirements.

The marketing version matches X.Y.Z. To support zero-major versions with a positive Apple build component, the bundle build version maps X.Y.Z to `(X+1).Y.Z`, with `bN` for betas. Components must fit four/two/two digits and beta N is 1 through 255. The archive and provenance filenames contain the full tag, runner and observed architecture. The public JSON records exact source commit, version, toolchain, signing status, checksum and resource inventory, with no absolute source/build paths. Archives normalize ZIP entry timestamps, preserve executable modes and omit debug symbols. The final App build remaps source prefixes and disables Swift debug output. Packaging refuses embedded /Users/ or /home/runner/ paths in the executable. This targeted check does not replace final privacy review.

## Opening an artifact

Unzip the archive and open the adjacent `Launch tap-n-filter.command`, not the raw app. The launcher derives `$HOME/Library/Application Support/tap-n-filter/versions/<tag>/library-v5.json` on the receiving machine and passes `--library-session-file` explicitly. It never copies, imports or falls back to pin/legacy data. Reopening the same version reuses that version's own saved file and can restore enabled assignments. A different version gets a different location. The launcher first refuses any AppKit-registered TNF owner matching its canonical bundle-ID family, tap-n-filter/TNF executable basename or TNF/tap-n-filter app-name family, or an unavailable/unknown owner result, without quitting or controlling any app. It then uses LaunchServices open without the new-instance flag instead of direct executable launch. Newly-created version directories use umask077 and mode700; existing directories are not chmodded. Fixture tests substitute inert owner/open tools and evaluate the generated JXA predicate in Node with fake AppKit objects, never querying real owners or executing the app. Node and Bash are needed for those focused tests.

This is a point-in-time registered-application check. It cannot exclude an unregistered direct CLI instance or an external launch race. Strict single-writer exclusion across those paths requires an App/source-owned mechanism and is not provided by this launcher. No global lock or ownership service is installed. Finder-opening the raw app has no production default data selection in current source and remains a source-owned follow-up. The launcher is a delivery adapter, not a source UI change.

## Publishing and reruns

Build jobs have read-only contents permission. Only the separate prerelease job has contents write permission, after both matrix legs pass. Eligible beta tags create a draft prerelease, upload only the two ZIP/provenance pairs, compare returned SHA256 digests and then publish it. It never marks a release latest. Stable tags stop at workflow artifacts. Publishing a stable release remains a separate deliberate owner action.

Concurrency serializes the same tag without canceling an active release. Workflow artifacts are immutable and are never overwritten. A publishing retry can finish a partial draft using the same downloaded bytes. Existing release metadata and asset digests must match exactly. Missing digests, unexpected assets, incomplete uploads or different bytes refuse, without deleting/replacing any asset. Rebuilding the same tag may yield different binary bytes; that is a refusal, not permission to replace an earlier release. Prefer rerunning only the failed publishing job with its original retained build artifacts. There is no automatic network retry.

Before any actual tag is pushed, the lead records privacy of source/notes/assets, rollback and version-owned data isolation, and the required local performance disposition. The first beta tag requires Release-configuration drag CPU at most 25% of one core, idle at most 1%, menu-open at most 3%, and zero writes during a drag. A lead-accepted overnight sound-OFF surrogate can satisfy only that scoped prerelease UI check. It does not establish sound-playing, physical-input or audio-thread performance or listening acceptance. Hosted CI does not manufacture those decisions. A stable release still waits for operator listening and the full release disposition. This workflow cannot enforce a human's decision to push a tag; it enforces tag/source/artifact correspondence after that deliberate action.

## Local checks and current limits

Run `python3 -B -m unittest discover -s tools/release -p 'test_*.py' -v` for bounded synthetic fixtures. Native signing/architecture outcomes and API writes are injected and labelled synthetic. They are not real build/signature/hosted-run evidence. Run `actionlint .github/workflows/release.yml` for workflow syntax. No helper installation is required. Any local compile or heavy check must use the project's private storage guard; hosted CI deliberately has no private guard dependency.

The isolated automation preparation does not fix source SDK compatibility or replace the current CI owner's changes. Merge those through their own review before tagging. An actual hosted tag run, archive launch, native signing result, listening acceptance and final outgoing asset privacy inspection remain pending.
